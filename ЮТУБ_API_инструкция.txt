Две вещи, которые ломают всю затею, если о них не знать заранее:

1. АУДИТ. Ролики, залитые через API из НЕпроверенного проекта,
   остаются приватными НАВСЕГДА. Отложенная публикация не сработает.
   Аудит запрашивается отдельно, рассматривают не мгновенно.
   → Пока аудита нет, заливать можно только для себя, не для зрителей.

2. РЕЖИМ «ТЕСТИРОВАНИЕ». Пока приложение в статусе Testing, токен
   доступа протухает через 7 дней, и авторизацию надо проходить заново
   каждую неделю. Лечится переводом приложения в Production.

└─────────────────────────────────────────────────────────────────┘

  Прямая ссылка:
  https://console.cloud.google.com/auth/overview?project=gen-lang-client-0342364734

  Google переделал этот раздел: вместо одной страницы «OAuth consent
  screen» теперь меню слева. Идти по нему СТРОГО в таком порядке —
  иначе создание клиента либо не даст, либо создаст непригодного:

  1) Branding
       название приложения, почта поддержки

  2) Audience
       • User type: External
       • Test users → добавить ВСЕ ТРИ почты
         ⚠ Аккаунт, которого нет в этом списке, Google НЕ ПУСТИТ
           авторизоваться. Самая частая причина «не работает».
       • Здесь же виден Publishing status: пока «Testing» —
         токены протухают через 7 дней (на три аккаунта это три
         переавторизации в неделю). Лечится кнопкой Publish app.

  3) Data Access
       добавить область:
         https://www.googleapis.com/auth/youtube.upload
       (для смены обложек через API ещё: .../auth/youtube.force-ssl)

  4) Verification Center
       здесь состояние проверки приложения. Без неё ролики,
       залитые через API, остаются приватными НАВСЕГДА.
       → Посмотри и запомни, что там написано.

  Позже, когда всё заработает — вернись сюда и нажми
  «Опубликовать приложение» (Publish app), иначе токены будут
  протухать каждые 7 дней.

┌─────────────────────────────────────────────────────────────────┐
│ ШАГ 6. АВТОРИЗАЦИЯ — ТРИ РАЗА, ПО ОДНОМУ НА КАНАЛ               │
└─────────────────────────────────────────────────────────────────┘

  Это ключевой момент для трёх каналов.

  Каналы на РАЗНЫХ аккаунтах Google, поэтому авторизацию проходим
  ТРИЖДЫ, каждый раз входя под своим аккаунтом.

  Проект при этом ОДИН — client_secret.json один и тот же на все три.
  Меняется только аккаунт, под которым входишь в браузере.

  Совет: делай это в окне «инкогнито» или выходи из аккаунта между
  заходами — иначе браузер молча подставит уже залогиненный, и токен
  уйдёт не на тот канал.

  Скрипт авторизации я напишу. Работать будет так:

      python youtube_auth.py канал1
      → открывается браузер
      → выбираешь аккаунт
      → ВАЖНО: если появится список каналов — выбери нужный
      → «Разрешить»
      → сохраняется .secrets/token_канал1.json

      python youtube_auth.py канал2     (выбираешь ВТОРОЙ канал)
      python youtube_auth.py канал3     (выбираешь ТРЕТИЙ канал)

  Проверить, что попал куда надо, можно будет сразу — скрипт напечатает
  название канала, к которому получил доступ.
