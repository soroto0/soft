## Что сделано в этой сессии

### Скорость и надёжность генерации кадров

| Проблема | Как проявлялась | Решение |
|---|---|---|
| Потоки падали до 1 вместо 4 | Лимит читался из `/account/usage`, который на простаивающем аккаунте отдаёт 0 | Лимит берётся из `/account/info` |
| 4 потока теряли 75% кадров | `RATE_LIMIT`, кадры молча подменялись стоком | `VEO_WORKERS=2` — замер: 8/8 против 2/8 |
| `VEO_UPSCALE=0` не работал для картинок | Читался только в коде видео | Распространён на картинки (74.5 → 51 с на фото) |
| Дешёвая локальная модель портила запросы | Переводила текст вместо описания кадра, в 5 раз медленнее | `LOCAL_PROMPT_MODE=0` |

**Замер на реальных данных:** 170 мин → **71 мин** (прогноз), 20/20 кадров без отказов.

### Рендер

- Аппаратное кодирование (NVENC/QSV/AMF) с автоопределением через **реальное
  пробное кодирование** — список `ffmpeg -encoders` врёт, там флаги сборки.
- Финальный проход **всегда** libx264: он определяет качество, а x264 при равном
  размере лучше NVENC. Видеокарта ускоряет только промежуточные файлы.
- Единый механизм отката `_run_enc()` во всех 7 точках кодирования: отказ
  аппаратного → повтор на процессоре → и только потом заглушка.
- Промежуточные файлы на быстрых пресетах (их перекодируют дважды).
- `scale` перед зумом 2x → 1.6x (максимальный зум 1.44).
- Починен `IndexError` на перекрывающихся таймкодах субтитров.

### Прочее

- `cancelled`/`expired` теперь терминальные статусы Veo — раньше опрос крутился
  до полного таймаута (30 мин) на **каждой** осиротевшей задаче.
- Журнал задач самоочищается (TTL 6 часов).
- `_env_switch`: пустая переменная (`VEO_FAST_MODE=`) больше не включает флаг.
- `.env.example` больше не раздаёт сломанную локальную модель новым клонам.
- `channels.upsert()` больше не стирает поля при редактировании канала из UI.
- Чекбокс «Цветокор по главам» заработал (расходились ключи `chapters` /
  `chapters_grade`).
- `agnes_chat` больше не отдаёт пустой ответ как успех.
- `.env.bak` закрыт в `.gitignore` (там были все ключи, репозиторий публичный).

## НЕ СДЕЛАНО — приоритетный список

### Ждёт решения пользователя

**Темп монтажа сломан.** Пресеты интенсивности практически неразличимы:
слабая/средняя/сильная/документальная дают 358/366/370/382 сцены. Кадр держится
3.8 с вместо заявленных 5 — это ещё и лишние 29% работы рендера.
Причина: `MAX_SCENE`-разбиение в `build_render_plan` (`render.py:~345`) режет
по потолку, а не к целевой длине. Фикс: `n = max(1, round(dur/5.0))`.
**Меняет вид ролика**, поэтому не трогал — нужно сначала посмотреть результат.

### P1 — ломает функциональность

1. **Водяной знак канала кладёт рендер.** `overlays.py:1440-1444` ставит
   `watermark` на всю длину ролика, а он рендерится Remotion'ом покадрово:
   12 мин × 30 fps = 21 600 полноэкранных PNG. Упрётся в таймаут `run_tree(900)`
   после ~15 минут впустую и десятков гигабайт временных файлов.
   Триггер: задать `watermark` любому каналу.
2. **`SMOKE_ITEMS` не определён** — `gen_remotion_gemini.py:174` его использует,
   но в репозитории такого имени нет. `apply_theme` пишет кандидата в живой
   `Overlay.tsx`, потом падает с `NameError`, и восстановление рабочей версии
   **не выполняется** — файл теряется. Триггер: запуск `gen_remotion_gemini.py`.
3. **`gen_variant` не может создать варианты `popup`/`collage`/`gallery`**
   и жжёт ~16 вызовов ИИ на каждую попытку. `_variant_smoke_test` подсовывает
   строку вместо картинки/пар → `FileNotFoundError`/`ValueError` на всех
   8 попытках. `_grow_variant_library` выбирает наименее покрытый тип, поэтому
   пытается снова **на каждом видео, бесконечно**.

### P2 — тихо портит результат

4. **`subs_on` перекрывает галочку пользователя** (`channels.py:163`) —
   снял «Вшить субтитры», а они всё равно вшиваются. Тот же класс бага, что
   уже находили с `ai_ratio`.
5. **Голос канала убивает «Разнообразие»** (`channels.py:171`): установка
   `voice` форсит `randomize=False`, а это заодно фиксирует интенсивность,
   цветокор, стиль субтитров и эффекты — все ролики канала выходят одинаковыми.
   Комментарий обещает защитить только голос.
6. **Кнопка «Стоп» вредит вне стадии ffmpeg.** `CANCEL` проверяется только
   внутри `render.py`. Нажатие во время озвучки/субтитров/раскадровки отменяет
   задачи Veo, но `auto_storyboard` продолжает работать — молча остаётся без
   картинок, `_busy` висит, а в конце всё равно запускается рендер.
7. **Утечка вариантов между каналами**, если в `meta.json` нет ключа `channel`
   (`overlays.py:1019-1026`) — тогда подходят варианты всех каналов.
   Триггер: проект создан через «Новый проект» + вставленный вручную сценарий.

### P3 — мелочи

- `render_counter` теряет дробную часть: `$3.5` рисуется как **`$35`**
  (`overlays.py:354`).
- `_render_remotion` не удаляет props-файлы — 34 осиротевших `tmp*_props.json`
  лежат в корне репозитория, у popup/collage внутри base64-картинки.
- `_hf_lint` проверяет весь проект `hyperframes/`: одна сломанная композиция
  валит все будущие HyperFrames-варианты.
- `yt_research.analyse:173` — при менее чем 13 роликах один и тот же попадает
  и в топ, и во флоп.
- `channels.bump_series`/`series_suffix` — мёртвый код, нумерация серий
  не работает.
- Задачи апскейла не регистрируются в журнале, поэтому «Стоп» их не отменяет.
- Глобальная переменная журнала задач может путать проекты при параллельной
  работе с двумя каналами.

   практике даже четвёрка не держится (сервер отвечает `RATE_LIMIT`, это лимит

   уточнить у поддержки, почему ключ на базовом плане. Это единственное, что
   снимет потолок по-настоящему.

## Настройки в `.env` (локальные, не в репозитории)

```
VEO_WORKERS=2          # проверено замером: 4 теряет кадры
VEO_UPSCALE=0          # 720p, быстрее; 1 = 1080p
VEO_FAST_MODE=1
VEO_VIDEO_RATIO=0.25   # доля живого видео; остальное — фото + Ken Burns
VEO_ANIMATE_PHOTOS=0
LOCAL_PROMPT_MODE=0    # НЕ включать: модель переводит вместо описания кадра
HW_ENCODE=1            # автоопределение NVENC/QSV/AMF
```

`ai_ratio` = **0.85** везде (интерфейс, `webapp.py`, `core.py`, все три канала).
