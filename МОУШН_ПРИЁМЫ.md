## 0. Что замерено своими руками

### 0.1 Длины планов в образцах владельца

`ffmpeg select='gt(scene,0.32)'`, весь ролик целиком:

| | own1 (насекомые) | own2 (кашалот) |
|---|---|---|
| длительность | 1118 с | 1268 с |
| планов | 116 | 36 |
| медиана плана | **4.34 с** | **16.97 с** |
| Q1 / Q3 | 2.68 / 11.56 с | 4.38 / 35.66 с |
| склеек в минуту | 6.2 | 1.7 |
| первая склейка | 19.52 с | 64.56 с |

Распределение у own1 двугорбое: 30 планов лежат в 2–3 с и одновременно
33 плана длиннее 10 с. То есть это не «ровный темп», а чередование
скороговорки и долгого разглядывания. У own2 темп втрое медленнее — это
согласуется с уже записанным в памяти замером Extremwelt.

**Вывод для нас:** одна длина плана на весь ролик — ошибка. Нужны обе
крайности в одном ролике.

### 0.2 Стоит ли кадр внутри плана

Метод: план декодируется в 160×90 серым, 10 к/с, считается среднее
`|разность соседних кадров|` из 255. Пол шума измерен на настоящем
стоп-кадре, размноженном тем же кодеком.

```
пол шума на стоп-кадре ............ 0.00 / 255   (ровно ноль)
own1: медиана по 8 планам ......... 1.53   минимум 0.16
own2: медиана по 8 планам ......... 4.29   минимум 1.61
замерших планов ................... 0 из 16
```

**Это самый важный замер ночи.** Настоящий стоп-кадр даёт РОВНО 0.00.
Ни один из 16 планов в обоих образцах владельца туда не попал — даже
самый спокойный даёт 0.16. В документалке кадр не стоит НИКОГДА. Наши
сцены, где SVG досчитал анимацию за первые 1.5 с и потом четыре секунды
висит неподвижная картинка, дают ровно 0.00 и читаются как вставленный
слайд.

## A. ПОЯВЛЕНИЕ

### A1. Линия рисуется, а не проявляется

*Где применяется:* все выноски, все стрелки, все контуры, все оси.
В `v2` это главный приём ролика; там же назван явно как единственно
верный: «анимировать прозрачность слоя вместо процедурной отрисовки»
стоит первым пунктом в списке «что убьёт эффект».

*Числа:* Trim Paths End 0 → 100 % за 20 кадров (0.66 с) при 29.97 fps,
ease-out с влиянием ручки 85 %. График скорости — несимметричный
колокол: разгон до ~2600 px/с за 0.15 с, потом затухание 0.5 с.

*Как повторить:*

```tsx
const L = 420;                       // измеренная длина пути
const draw = interpolate(frame, [0, span * 0.22], [L, 0], {
  easing: Easing.bezier(0.16, 1, 0.3, 1),
  extrapolateLeft: 'clamp', extrapolateRight: 'clamp',
});
<path d={d} stroke="#e9f2f6" strokeWidth={2} fill="none"
      strokeDasharray={L} strokeDashoffset={draw} />
```

Длину пути для прямой считаем сами (`Math.hypot`), для дуги берём с
запасом — лишний dasharray не виден.

*Пример:* `v2` — выноска над One World Trade Center; `own2` — зелёные
акустические лучи от головы кашалота.

### A2. Порядок сборки выноски: якорь → линия → плашка → текст

*Где применяется:* любая подпись, указывающая на предмет. Это самый
воспроизводимый рецепт из всей ночи, потому что в `v2` он выдан
покадрово.

*Числа (v2, готовый результат на экране):*

| элемент | старт | длительность | чем |
|---|---|---|---|
| кружок-мишень | 0 мс | 0.40 с | scale 0→1, перелёт `cubic-bezier(.175,.885,.32,1.275)` |
| линия-выноска | 250 мс | 0.80 с | trim/dashoffset, `cubic-bezier(.16,1,.3,1)` |
| плашка под текст | 700 мс | 0.50 с | scaleX 0→1 от левого края |
| сам текст | 850 мс | 0.40 с | clip-path слева направо + сдвиг Y с +8 px |

Вся выноска собирается 1.25 с. Ни один элемент не появляется
одновременно с соседом.

*Как повторить:* на каждый элемент своя `interpolate` со сдвинутым окном:

```tsx
const ring  = interpolate(frame, [0,          span * 0.08], [0, 1], EO);
const line  = interpolate(frame, [span * 0.05, span * 0.20], [0, 1], EO);
const plate = interpolate(frame, [span * 0.14, span * 0.24], [0, 1], EO);
const label = interpolate(frame, [span * 0.17, span * 0.25], [0, 1], EO);
```

**Осторожно с хелпером.** Напрашивается свернуть эти четыре строки в
функцию `at(delay, len)`. Так делать НЕЛЬЗЯ: приёмка в `gen_scenes.py`
(строка 1008) считает вхождения подстроки `interpolate(` в исходнике и
отвергает файл при `< 3`. Сцена с хелпером имеет одно вхождение и будет
забракована как «неподвижная» — при том что движения в ней больше, чем в
проходящей. Общими можно делать только настройки:
`const EO = { easing: Easing.bezier(0.16,1,0.3,1), extrapolateLeft: 'clamp',
extrapolateRight: 'clamp' } as const;` — это объект, а не вызов, и счётчик
он не трогает.

*Пример:* `v2`; в `own2` тот же порядок в упрощённом виде — белая плашка
раскрывается scaleX от левого края за 0.5 с, текст проявляется через
400 мс после начала раскрытия плашки, а не вместе с ней.

### A3. Ступенька между братьями (stagger)

*Где применяется:* столбцы диаграммы, строки текста, слои разреза,
деления шкалы — всё, чего больше одного.

*Замеренные величины:*

| источник | что | ступенька |
|---|---|---|
| `v4` | 4 столбца диаграммы | **80 мс** |
| `v4` | 4 колонки светлой темы | 100 мс |
| `v7` | 3 строки заголовка | 100 мс |
| `v8` | 6 столбцов диаграммы | **120 мс** |
| `v2` | элементы выноски | 200–450 мс |
| `v5` | соседние слои-полигоны | 500 мс (шаговые ключи) |

`v4` называет одновременный рост всех четырёх столбцов первым пунктом
списка «что убьёт эффект».

*Как повторить:* задержка от индекса внутри `.map()` — той самой,
которой уже требует наш промпт для плотности:

```tsx
{bars.map((b, i) => {
  const g = interpolate(frame,
    [span * (0.10 + i * 0.05), span * (0.10 + i * 0.05 + 0.18)], [0, 1],
    { easing: Easing.out(Easing.cubic),
      extrapolateLeft: 'clamp', extrapolateRight: 'clamp' });
  return <rect key={b.name} y={base - b.h * g} height={b.h * g} … />;
})}
```

При span = 6 с × 30 fps шаг 0.05 даёт ровно 90 мс — попадает в
замеренный коридор 80–120 мс.

### A4. Не из нуля и не из прозрачности

*Где применяется:* карточки, врезки, плашки, иконки.

*Числа:* `own1` — плашка 0.85 → 1.0; `own2` — врезка 0.30 → 1.0 за 0.6 с,
карточки слов 0.85 → 1.0 за 0.1 с; `v4` — заголовок 92 % → 100 %;
`v7` — контур 90 % → 100 %.

Ни одного случая «просто opacity 0 → 1» без второго свойства. Всегда
пара: масштаб + прозрачность, или сдвиг + прозрачность.

*Как повторить:* `opacity` умножаем как обычно, а рядом обязательно
`transform`:

```tsx
const pop = interpolate(frame, [0, span * 0.12], [0.88, 1], {…});
<g transform={`translate(${cx} ${cy}) scale(${pop}) translate(${-cx} ${-cy})`}
   opacity={a}>
```

### A5. Перелёт — только на одном элементе

*Где применяется:* кружок-мишень выноски (`v2`), нажатая кнопка
(`own1`, `own2`), появление круга (`v3`).

*Числа:* `v2` — `cubic-bezier(.175,.885,.32,1.275)`, доходит примерно до
110 % и садится; `v3` — «доходит до ~110 % перед посадкой на 100 %»;
`own1`/`own2` — импульс сжатия 1.0 → 0.95 → 1.0 за 150 мс.

Важно: перелёт нигде не стоит больше чем на одном элементе кадра. Всё
остальное садится без отскока.

*Как повторить:*

```tsx
const s = interpolate(frame, [0, span*0.06, span*0.10], [0, 1.10, 1.0],
  { easing: Easing.out(Easing.quad), extrapolateRight: 'clamp' });
```

### A6. Текст выезжает снизу на 8–40 px

*Числа:* `v2` — +8 px; `v4` — +30 px; `own2` — +40 px; `v7` — +450 px
(это уже не подпись, а полноэкранная вырезка).

Чем мельче текст, тем короче путь. Для подписи под схемой правильный
порядок величины — **8–20 px**, а не половина кадра. В нашем рабочем
примере в `CODE_PROMPT` уже стоит `rise` 18 → 0 px: это попадание.

### A7. Цифра набегает, а не появляется

*Где применяется:* всё, где в дикторском тексте названо число. В `v8`
заголовок набирается по буквам с мигающим курсором (1 Гц, красный
`#D32F2F`, 3 px).

*Как повторить:* число — производная от того же прогресса, что и
геометрия, и округляется на выводе:

```tsx
const v = interpolate(frame, [span*0.15, span*0.55], [0, 118], {…});
<text …>{Math.round(v)}</text>
```

Так цифра на подписи и высота столбца показывают одно и то же — они
физически одна переменная.

## B. ДЕРЖАНИЕ

### B1. Собралось — и стоит долго

*Числа:* `v2` — 14.5 с; `v4` — 25.0 с; `v8` — 40 с; `own2` —
полноэкранная схема с акустикой держится **10.8 с**, врезка 3.0 с,
нижняя плашка 3.5 с.

То есть сборка занимает первые 15–25 % времени, остальное — покой.
Обратное (анимация тянется до последнего кадра) в разборах не встретилось
ни разу.

*Как повторить:* все `interpolate` заканчиваются не позже `span * 0.6`.
У нас `Scene.tsx` гасит сцену за последние 0.45 с, значит анимация должна
закончиться заведомо раньше — иначе элемент уезжает и гаснет
одновременно, и оба движения смазываются.

### B2. Держится — но не замирает

Замер 0.2 говорит: настоящий стоп-кадр даёт 0.00, а в образцах владельца
такого нет ни в одном из 16 планов.

В моушн-графике то же решается по-другому, чем в съёмке: сама графика
стоит неподвижно (`v2`, `v4`, `v7`, `v8` — все пишут «0 px дрейфа»), а
шевелится **фон и рамка**:

* `v4` — частицы фона ползут вверх на +2 px за 1.5 с;
* `own2` — фоновый слой частиц идёт ~15 px/с;
* `own1` — внутри врезки контент едет `scale 1.00 → 1.03` за 0.4 с,
  при том что рамка врезки стоит.

У нас фон уже живой — `Backdrop` даёт свет, 46 пылинок, зерно и виньетку.
Значит нехватка ровно одна: **сама схема должна очень медленно ехать**
(см. D1), иначе живёт только подложка, а рисунок поверх неё мёртвый.

## C. УХОД

### C1. Уход — зеркало входа, но вдвое быстрее

*Числа:* `v2` — линия сматывается обратным trim и плашка схлопывается
scaleX 1 → 0 за **0.6 с**, `cubic-bezier(.7,0,.84,0)` (ease-**in**, не
out); вход тех же элементов занимал 1.25 с.

*Как повторить:* в нашем контракте `p.exit` уже даёт 0.45 с общей
затухающей. Отдельный уход геометрии нужен только тогда, когда сцена
длинная: домножить `strokeDashoffset` на обратный прогресс в последние
20 % и получить смотку.

### C2. Схлопывание в линию

*Где применяется:* полноэкранные текстовые карточки в `own2`: текст
сжимается `scaleY 1 → 0.05`, одновременно `scaleX → 0`, за 0.2 с с
ease-in, схлопываясь в точку по центру, и только потом идёт рез.

Приём даёт «щелчок» на стыке и стоит копейки.

### C3. Резать жёстко

По всем разборам жёсткий рез — самая частая склейка: `own2` — 5 из 5,
`v4` — 3 из 4, `v5`, `v7`, `v8` — 100 %. Исключение одно и важное: см. E.

## D. КАМЕРА

### D1. Медленный наезд поверх всего (Ken Burns)

*Замеренные величины:*

| источник | движение | за сколько |
|---|---|---|
| `own1` | scale 1.00 → 1.03 | 3.9 с |
| `own1` | scale 1.00 → 1.05 | 6.7 с |
| `own1` | scale 1.00 → 1.08 | 4.1 с |
| `own2` | scale 1.00 → 1.05 | 4–6 с, на **всех** съёмочных планах |
| `v2` | scale 1.00 → 1.03 + сдвиг −30 px | 10 с |
| `v4` | scale 1.00 → 1.02 (титр) | 1.5 с |

То есть 1.5–2 % в секунду, никогда не больше 8 % за план.

*Как повторить в сцене:* обернуть **весь** рисунок одной группой и дать
ей масштаб от кадра. Это одна строка, а даёт ровно то, чего нашим сценам
не хватает:

```tsx
const push = interpolate(frame, [0, span], [1, 1.045], {
  easing: Easing.inOut(Easing.quad),
  extrapolateLeft: 'clamp', extrapolateRight: 'clamp',
});
…
<svg width="62%" viewBox="0 0 420 250">
  <g transform={`translate(210 125) scale(${push}) translate(-210 -125)`}>
    …весь рисунок…
  </g>
</svg>
```

Центр масштабирования — центр viewBox, иначе рисунок уползёт из кадра и
приёмка получит пустой рендер.

### D2. Параллакс по глубине вместо зума картинки

*Где применяется:* `v1` — вся техника ролика. 2D-слои разнесены по Z:
0, 500, 1200, 2000, 4000 px; камера 50 мм едет по Z с −2666.7 до −600 за
2.0 с, F9 Easy Ease, влияние 65 %.

`v1` прямо называет главной ошибкой «сплющить Z и зумить всю картинку
целиком как один слой».

*Как повторить без 3D:* каждый слой едет со своим множителем — дальний
почти стоит, ближний идёт быстрее:

```tsx
const k = [0.15, 0.4, 1.0];             // задний, средний, передний
{k.map((f, i) => (
  <g key={i} transform={`scale(${1 + (push - 1) * f})`}>…</g>
))}
```

Для разреза это бесплатно: слои материала уже нарисованы отдельно.

### D3. Наезд на деталь

*Числа:* `v5` — scale 1.00 → 2.10 за 0.3 с, ease-in-out, и обратно за
0.2 с; `v3` — вид отъезжает 1.00 → 0.45 за 0.5 с, чтобы показать всю
схему, потом возвращается.

Рабочая пара: показать целое → нырнуть в узел → вернуться. В сцене на
6 секунд помещается один такой нырок.

### D4. Проезд вдоль ряда

*Где применяется:* `own1`, секунды 22–29 — спрайты с датами едут
горизонтально с постоянной скоростью **−120 px/с**, и разбор отдельно
отмечает: сделай это слайдами, и вместо фильма получится презентация.

*Как повторить:* `translateX` линейно от кадра, ряд шире viewBox.
Для «шкалы времени», «этапов», «сравнения пяти штук» это лучше, чем
показать всё сразу мелко.

### D5. Орбита вокруг объёмного

`v6` (единственный ролик с настоящей 3D-визуализацией разрушения):
за 60 с — три орбиты, азимут ~120°, ~90°, наклон ~30°, каждая 3.5–13.3 с,
всегда ease-in-out. Резов нет вообще: **0 жёстких склеек за минуту**,
переход между состояниями — сама орбита.

Для наших SVG-схем ближайший честный эквивалент — не подделывать 3D, а
менять ракурс изометрии: сдвигать точки по формуле изометрии с медленно
меняющимся углом.

## E. СКЛЕЙКИ

### E1. Белая вспышка на 3 кадра

*Числа:* `own1` — `#FFFFFF` на 100 % непрозрачности, **3 кадра** (0.1 с),
на выходе из графической врезки обратно в съёмку. Отдельно назван как
третий пункт «что убьёт эффект»: замена вспышки на кросс-фейд или
жёсткий рез «убирает всплеск, нужный при возврате».

`v1` — то же на 10 кадров жёлто-белым, поверх Add, чтобы спрятать
перестановку камеры. `v4` — белая вспышка 12 кадров.

*Как повторить:* ffmpeg-фильтр на стыке или отдельный кадр-вставка в
раскадровке. В Remotion — `AbsoluteFill` с белым и треугольной
прозрачностью на 3 кадра.

### E2. Цветной блок на 2 кадра

`own1`, секунда 1.2: между планами вставлен сплошной `#68661C` на 2 кадра
— «оптический разрыв ритма». Дешевле вспышки и не слепит.

### E3. Кросс-фейд 6–8 кадров — только в спокойных местах

`own1` в первую минуту: 5 кросс-фейдов по 6–8 кадров против 4 жёстких
резов. То есть в открывающей, «дышащей» части документалки мягкие склейки
преобладают, а дальше по ролику — жёсткий рез.

### E4. Рез на удар

`own2`: 5 склеек из 11 — текстовые карточки, поставленные ровно на
перкуссионные удары в музыке. Это тот же приём, что у нас уже есть в
`sfx_library`, но применённый к появлению ГРАФИКИ, а не к смене кадра.

## F. ТИПОГРАФИКА

### F1. Кегль по назначению

Замеренная высота прописной в процентах от высоты кадра:

| назначение | источник | кегль |
|---|---|---|
| подпись на схеме, ось, деление | `own2` 1.8 %, `v6` 1.4 %, `v3` 2.0 %, `v4` 2.5 % | **1.4–2.5 %** |
| нижняя плашка, титр врезки | `own2` 2.8–3.2 %, `v2` 3.8 %, `v8` 3.5 % | **2.8–3.8 %** |
| полноэкранная карточка-утверждение | `own2` **10 %**, `v7` 8 %, `v4` 6 % | **6–10 %** |

Наш рабочий пример даёт подписи `fontSize 9` при `viewBox` высотой 250 —
это 3.6 % высоты рисунка, и это правильный порядок. А заголовок 34 px на
1080 — 3.1 %: для подписи хорошо, для карточки-утверждения втрое мелко.

### F2. Трекинг противоположный для двух ролей

`own2` — карточки-утверждения: трекинг **+60…+80/1000** (широко);
`v4` — титр +0.15 em; `v7` — заголовок **−20** (плотно); `v8` — цифры
годов −0.02 em.

Правило: широкий трекинг у крупного разрежённого текста, плотный — у
плотных данных. Средний трекинг везде — это «шрифт по умолчанию».

### F3. Плашка, а не тень

Ни в одном из 15 разборов текст не несёт тени или обводки. Читаемость
везде решается ПЛАШКОЙ:

* `own2` — белая `#FFFFFF` плашка 75 % ширины кадра × 7 % высоты,
  скругление 8 px, текст `#000000` поверх;
* `v2` — белая плашка **112 % ширины текста × 145 % высоты прописной**;
* `v7` — красные `#E31A45` прямоугольники под каждой строкой, отступ
  12 px со всех сторон, текст чёрный;
* `v8` — тёмная капсула `#262626` высотой 42 px, скругление 21 px
  (то есть ровно половина высоты — «таблетка»).

Тень есть, но не у текста, а у ПЛАШКИ: `own2` — `#000000` 35 %, размытие
20 px, сдвиг Y +10 px.

Это ровно то, что в проекте уже сделано коммитом про `scrim` — но там
речь про оверлеи над съёмкой; в сценах-схемах плашка под текстом сейчас
не обязательна, а по разборам должна быть, когда подпись ложится на
рисунок.

### F4. Пропорция плашки

Из `v2`: 112 % / 145 %. То есть по горизонтали запас маленький (6 % с
каждой стороны), а по вертикали большой (22 % сверху и снизу). Плашка
получается «приплюснутая» — это и отличает её от рамки вокруг текста.

## G. УСТРОЙСТВО РИСУНКА

### G1. Сетка под данными

`v4` называет отсутствие сетки третьим пунктом «что убьёт эффект»:
без неё столбцы «висят без опорного контекста». Числа: сетка 10×10,
штрих 1 px, `#333333`, прозрачность **40 %**, появляется отдельно от
данных за 0.3 с линейно.

`v8` — 3 горизонтальные пунктирные линии, штрих `8 8`, 40 %, на 25/50/75 %
от максимальной высоты столбца.

*Как повторить:* `.map()` по `[0.25, 0.5, 0.75]` — три строки кода,
и рисунок перестаёт быть набором фигур на пустоте.

### G2. Общая опорная линия

`v8`: под всеми шестью столбцами лежит одна сплошная капсула `#262626`
высотой 42 px со скруглением 21 px, «связывающая точки данных вместе».
Она входит первой — scaleX 0 → 1 за 0.5 с, `cubic-bezier(.16,1,.3,1)` —
и только потом по ней растут столбцы.

Это важный порядок: **сначала основание, потом то, что на нём стоит.**

### G3. Пунктир и сплошная как разные смыслы

`own2`, схема эхолокации: несфокусированный звук — 4 пунктирные линии
(`#68AC41`, 3 px, dash `6 4`), расходящиеся веером под 15°, 25°, 35°, 45°
от точки на голове; сфокусированный — ОДНА сплошная линия 4 px в ту же
зелёную сторону, упирающаяся в 5 вертикальных оранжевых импульсов
(`#D9531E`, 4 px, высота 32 px, шаг 12 px).

Один и тот же цвет, разная фактура линии = разное состояние. Это дешевле
и понятнее, чем второй цвет.

### G4. Цветовая рампа для величины

`v6`: кривые напряжений раскрашены зелёный `#3A9D23` → жёлтый `#FFE600`
→ красный `#E31B23` по величине смещения, толщина 3–5 px. Серые
волосяные линии 1 px связывают цветные узлы с несущими узлами
конструкции.

Три цвета — не украшение, а шкала. У нас в палитре уже есть
`#e0b44c` и `#d0523f`; не хватает зелёного конца, но для «норма → предел
→ разрушение» хватит и пары амбер/красный от холодного серого.

### G5. Изометрия под 30°

`v5`: вершины полигона обязаны лечь ровно на изометрическую сетку
базового чертежа, **30° / 150°**; несовпадение угла названо первым
пунктом «что убьёт эффект».

*Как повторить:* точка `(x, y, z)` → экран
`X = (x − y) * cos30`, `Y = (x + y) * sin30 − z`. Шесть строк, и разрез
перестаёт быть плоским прямоугольником.

### G6. Один акцент — и он приходит последним

Акцентный цвет во всех разборах ровно один и лежит на одном классе
объектов:

| ролик | акцент | на чём |
|---|---|---|
| `own2` | `#68AC41` + `#D9531E` | лучи звука и импульсы |
| `v4` | `#FFC800` | заливка столбцов |
| `v6` | `#FFE600` | кривая предельного напряжения |
| `v7` | `#E31A45` | плашки, контур, полоса на глазах |
| `v8` | `#E53935` | только активное состояние |
| `v5` | `#FE00EC` | только пятно застройки |

У нас это правило уже записано пунктом (d). Чего в промпте нет — что
акцентный элемент должен приходить **последним** по времени. Во всех
разборах он входит в конце сборки, а не первым.

## H. ЧТО ИМЕННО ОТЛИЧАЕТ ОТ ПОКАЗА КАДРОВ

Сводка по десятым пунктам всех 15 разборов — что назвали «сломает
иллюзию». Повторяющееся:

1. **Линейная интерполяция.** Названа в `v1`, `v2`, `v4`, `v6`, `v7` —
   пять раз из десяти роликов. Всегда с одинаковой формулировкой: без
   ease-out движение «роботизированное», «не киношное». Замеренная форма
   кривой: пик скорости в первые 15 % интервала, потом длинное затухание.
2. **Одновременное появление.** `v4`, `v7` — прямым текстом: убери
   ступеньку 80–100 мс, и вместо анимации получится статичный плакат.
3. **Ничего не движется.** `own1` — «без непрерывного проезда −120 px/с
   это выглядит как слайд-дек»; `own1` (другой кусок) — «без медленного
   наезда 1.00 → 1.03 сцена читается как слайдшоу фотографий».
4. **Прозрачность вместо отрисовки.** `v2` — второй пункт.
5. **Нет плашки под текстом.** `own2` — второй пункт: чёрный текст прямо
   по подводной съёмке нечитаем.
6. **Нет опорной сетки/основания.** `v4` — третий пункт.
7. **Размытие движения.** `v7` — в панели слоёв включён Motion Blur на
   графических слоях. В Remotion его нет даром; ближайшая замена —
   короткий шлейф: тот же элемент вторым экземпляром с задержкой в 2
   кадра и прозрачностью 0.25.

## ЧТО ВПИСАТЬ В ПРОМПТ СЦЕН

Готово к вставке в `gen_scenes.CODE_PROMPT`. Дублирование проверено
поиском по строкам 205–397 `gen_scenes.py`: слов `stagger`, `dashoffset`,
`ease-out`, `grid`, `isometric`, `overshoot`, `drift`, `cap height`,
`tracking`, `baseline`, `textShadow` там нет ни одного. Два совпадения
есть, но мнимые: `strokeDasharray` встречается один раз в рабочем примере
как СТАТИЧНЫЙ пунктир маркера (`strokeDasharray="4 3"`), а не как способ
отрисовки; слово `plate` — в пункте 4 про то, что непрозрачная заливка
маленькой плашки разрешена, а не про её геометрию. Пункты 1–11
существующего контракта (unused locals, `p.enter * p.exit`, прозрачный
корень, три `interpolate`, `useVideoConfig`, плотность 8–20 элементов,
выноски с поводком, размерные линии, один акцент, разрез, 120 строк)
ниже не повторяются.

```
MOTION CONTRACT — measured on 10 real documentary / motion-graphics films
on 2026-09-02. These are not style preferences; each one is the difference
between a drawn film shot and a slide.

12. NOTHING ARRIVES AT THE SAME TIME AS ITS SIBLING. Whenever you .map()
    over an array, the delay MUST depend on the index. Measured stagger
    between siblings in real work: 80 ms (VOX bar chart), 100 ms (title
    lines), 120 ms (bar graph), 200-450 ms (callout parts). Write it as
    `[span * (0.10 + i * 0.05), span * (0.28 + i * 0.05)]`. All bars
    growing together is the single most named mistake in the breakdowns
    and reads as a static poster.
    Write every interpolate() call out IN FULL. Do NOT wrap them in a
    helper like `const at = (d, len) => interpolate(...)` — an automatic
    check counts the literal occurrences of `interpolate(` in your file and
    rejects it below three, so a helper gets your scene thrown away for
    being motionless no matter how much actually moves. Sharing the options
    object is fine: `const EO = { easing: Easing.bezier(0.16, 1, 0.3, 1),
    extrapolateLeft: 'clamp', extrapolateRight: 'clamp' } as const;`

13. LINES ARE DRAWN, NOT FADED IN. Every leader line, arrow, axis, outline
    and contour must animate `strokeDashoffset` from its own length down
    to 0 over 0.5-0.8 s. Compute the length (Math.hypot for a straight
    segment) and set `strokeDasharray={L} strokeDashoffset={L * (1 - t)}`.
    Animating a line's opacity instead is explicitly called out as the
    thing that destroys the effect.

14. ASSEMBLE A CALLOUT IN THIS ORDER, NEVER ALL AT ONCE: the anchor marker
    first (a small ring or dot ON the thing being named, scale 0 -> 1 with
    a slight overshoot to 1.10), then the leader line drawing outward
    starting 250 ms later, then the label plate expanding scaleX 0 -> 1
    from the end nearest the line at 700 ms, then the text itself at
    850 ms. Total 1.25 s. This exact sequence is the standard.

15. EASE-OUT, NEVER LINEAR. Arrivals use Easing.bezier(0.16, 1, 0.3, 1) or
    Easing.out(Easing.cubic): a hard velocity peak in the first 15 % of the
    interval, then a long settle. Linear interpolation on an entrance is
    named as a failure in five of the ten films. Only a constant travelling
    motion (a dot running along a path, a row sliding past) may be linear.

16. THE WHOLE DRAWING MUST DRIFT. Wrap the entire SVG content in ONE <g>
    and scale it 1.00 -> 1.04 across the full duration, about the centre
    of the viewBox:
      <g transform={`translate(cx cy) scale(${push}) translate(-cx -cy)`}>
    Measured in the reference films: 1.5-2 % per second, never more than
    8 % across one shot. A frozen picture measures exactly 0.00 frame
    difference; not one shot in either owner reference does that.

17. EVERYTHING SETTLES EARLY. All interpolate() output ranges must finish
    by span * 0.6 at the latest, so the scene stands assembled and calm for
    its last 40 %. Real graphics hold still for 10-40 s after a 1-2 s
    build. An animation still running at the last frame collides with the
    player's own 0.45 s fade-out and smears.

18. ENTER WITH TWO PROPERTIES, NEVER OPACITY ALONE. Pair opacity with
    either scale (start at 0.88, not 0) or an 8-20 px offset in y. A pure
    opacity fade is what a slideshow does.

19. THE ACCENT ELEMENT ARRIVES LAST. The one thing carrying the accent
    colour — the crack, the failing member, the overload arrow — must be
    the final element to appear, after the structure it sits on is already
    drawn. It is also the only element allowed an overshoot.

20. FOUNDATION FIRST. Draw the ground line, base rail or axis before
    anything stands on it: the baseline expands scaleX 0 -> 1 over 0.5 s,
    and only then do the bars/layers/columns grow from it.

21. PUT A GRID OR RULE BEHIND THE DATA. Three to ten hairlines at 1 px,
    at 25/50/75 % of the plot height, drawn in the palette grey at 0.35-0.40
    opacity, fading in over 0.3 s separately from the data. Bars floating
    on emptiness with no reference lines is named as a failure.

22. TEXT SITS ON A PLATE, NEVER ON A SHADOW. No textShadow, no stroke on
    text anywhere. If a caption overlaps the drawing, put an opaque plate
    behind it: 112 % of the text width and 145 % of its cap height, corner
    radius small (4-8 px) or exactly half the height for a pill. Dark text
    on a light plate, or light text on a plate at least 60 % opaque.

23. SIZE TYPE BY ITS JOB, measured as cap height against frame height:
    axis ticks and part labels 1.4-2.5 %, the scene caption 2.8-3.8 %, and
    a full-frame statement 6-10 %. Track wide (+0.06em) only on the large
    sparse text and tight (-0.02em) on dense numerals — never the same
    tracking on both.

24. A NUMBER MUST COUNT UP, not appear. Any figure named in the narration
    is derived from the same interpolate() that drives its geometry, and
    printed with Math.round(). The digits and the bar height are then
    literally the same variable, and the viewer sees the quantity change.

25. TEXTURE CARRIES MEANING, NOT DECORATION. Use one colour and vary the
    stroke instead of adding a second colour: dashed strokeDasharray="6 4"
    for the uncertain / diffuse / before state, solid for the focused /
    measured / after state, in the same hue. Reserve a second hue for a
    true value ramp (cold grey -> amber -> red = safe -> limit -> failure).

26. IF THE SUBJECT IS A SOLID, DRAW IT IN ISOMETRIC, not as a flat
    rectangle: X = (x - y) * 0.866, Y = (x + y) * 0.5 - z. Keep every
    receding edge on the 30 deg / 150 deg grid — a mismatched angle is the
    first thing that reads as wrong.
```

## Слабое место разбора

Числа кроме двух разделов (0.1 и 0.2) — это чтение модели с экрана, а не
мой замер. Там, где модель читала цифры прямо из интерфейса After Effects
(v2: Trim Paths 0→20 кадров; v1: камера −2666.7 → −600 за 60 кадров;
v8: ключи на 0 и 42 кадре), им можно верить как экранному тексту.
Ступеньки в 80 и 120 мс модель оценивала на глаз по кадрам — порядок
величины верный, точность до десятков миллисекунд не гарантирована.
На это опираться можно: разница между 80 и 120 мс не видна, а разница
между 0 и 100 мс — та самая, ради которой всё писалось.
